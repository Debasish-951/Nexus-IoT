Nexus IoT · Home dashboard · Combined concept

One page, three audiences

A + B + C merged into a single landing page. Rather than stacking twenty widgets, the page is arranged in four bands, each answering one question in the order a person actually asks them. An operator stops reading after band 2. A manager reads band 1 and band 4. An engineer lives in band 3. Nobody has to scroll past things that aren't theirs to find the thing that is.

Band 1 · Health Index, KPIs, hierarchy — from B Band 2 · Triage queue, attention list — from A Band 3 · Live tiles, correlated chart, quality — from C Band 4 · Trends, worst performers, connectivity — from A + B

One thing that is deliberately not here: per-role variants. The bands do the same job — an operator reads 1–2 and stops, a manager reads 1 and 4, an engineer lives in 3 — without four separate layouts to maintain. RBAC still applies to the actions (Acknowledge, Rotate, Bind are hidden if can(...) says no), but the layout is one thing, not five.
Two decisions I need from you before building:
1. The Health Index formula — my proposal is above; tell me if the weights should favour downtime over alarm count, or vice versa.
2. Band order — as drawn, an operator has to scroll past the Overview band to reach their queue. Swapping bands 1 and 2 fixes that but pushes the manager's view below the fold. Say which audience wins, or I'll make it a per-user preference.
