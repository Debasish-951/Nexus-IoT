Five replacements for the current landing page

Each concept below is a full mockup of what sits to the right of the sidebar when someone signs in. They are drawn with your dark theme tokens and populated with plausible data from your own tables — assets, alarms, alarm_history, telemetry, seen_devices, activity_logs, brokers. Every widget is tagged live if today's API already returns the data, or new if it needs a new query. Pick one — or name the widgets you want and I'll assemble a sixth.

A · Operations Command Centre

The landing page answers one question: what needs a human right now? Nothing on the screen is a count for its own sake — every number is a queue you can work through, and every row has an action attached. This is the concept that most directly fixes what you're seeing today, because "0 assets / no active alarms" becomes a triage board that still carries signal when nothing is on fire (staleness, unmatched devices, rules that never fire).

The one decision this concept needs from you: the Health Index formula. My suggestion — start at 100, subtract weighted points for open alarms by severity, for assets with stale telemetry, and for downtime minutes in the window. Simple, explainable, tunable. A score nobody can explain gets ignored within a fortnight.

It is the friendliest of the five and the one that makes the platform feel used rather than installed.

What has to be built, whichever you pick

ItemWhyWhere
GET /dashboard/attention Merges open alarms, assets whose newest telemetry is older than their expected interval, unbound device IDs and expiring API keys into one ranked list. This single endpoint powers the main widget in A, D and E. routes/dashboard.ts
GET /dashboard/alarm-trend Hourly or daily buckets from alarm_history, plus MTTA and MTTR. Needed by A, B and E. routes/dashboard.ts
GET /dashboard/ingest-series Per-minute telemetry counts. Today /dashboard/summary gives one number, which cannot tell "quiet" from "broken". routes/dashboard.ts
Route rules in ROUTE_RULES Deny-by-default means every new route 403s until it is mapped — this is exactly the error you hit on the viz-nodes endpoint. middleware/authorize.ts
OpenAPI spec + codegen The contract is generated. New routes go in openapi.yaml, then pnpm --filter @workspace/api-spec run codegen. lib/api-spec/src/openapi.yaml
Empty-state treatment The actual fix for your screenshot. Any concept can carry it; only E has it designed in. pages/Dashboard.tsx
