Round 2 · three new directions

UI concepts for WS Integrated Suite

Round 1 explored structured enterprise, calm SaaS, control-room and editorial treatments. None landed. These three deliberately leave that territory: one strips decoration back to type and hairlines, one adopts the familiar cloud-console shape, and one changes the layout model rather than the styling. Every screen is real content from this platform — assets, telemetry, alarms, API endpoints, access control.

How to review these. Each page has a tab bar for six screens and a Desktop / Mobile toggle. The amber note at the top of every screen says what that concept changes and why. If a direction is close but not right, say which parts work — colour, density, layout model — and the next round narrows rather than starts over.

The three concepts

5

Slate — Quiet Precision

Monochrome first · no cards · hairlines and whitespace · one accent
Open Slate

Structure comes entirely from alignment, hairlines and space. No card borders around KPIs, no tinted icon chips, no shadows, no gradients. Deep teal appears in exactly three places: the primary button, the active nav item, and the primary data series. Every identifier and measured value is monospace, so a device ID never reads as prose.

Strengths

  • Ages slowly. Nothing here is a 2026 styling trend, so it won't look dated in three years.
  • Data is the loudest thing. Removing box borders makes the numbers the first thing the eye lands on.
  • Cheapest to build. Fewest visual primitives, so the least CSS and the fewest edge cases.
  • Prints and screenshots well — relevant for shift reports and audit packs.

Trade-offs

  • Reads as austere to users who expect a friendlier product surface.
  • Grouping is implied, not drawn — spacing must be exact or sections blur together.
  • Little room for brand expression beyond the single accent.
6

Nimbus — Cloud Console

Soft blue-grey canvas · white rounded cards · drawers not modals · deliberately familiar
Open Nimbus

The shape your operators already know from Azure IoT Central, AWS IoT and Google Cloud: a site picker at the top of the sidebar, grouped nav with monochrome icons, page-level tabs, white rounded cards on a soft canvas, labelled status pills, and a right-hand drawer for creation so the list behind it stays visible. Chosen for low training cost, not for novelty.

Strengths

  • Near-zero learning curve. Anyone who has used a cloud console can operate it on day one.
  • Reads as enterprise-credible in a procurement demo — the strongest option if you sell this.
  • Drawers keep context. Cancelling a form never loses your filters or scroll position.
  • Roomiest for growth — banners, toasts, empty states and wizards all have an obvious home.

Trade-offs

  • Least distinctive. It will be compared to the platforms it resembles, favourably or not.
  • Card padding costs density — around 12 table rows where Workbench fits 22.
  • Blue is the expected IoT accent, so it contributes nothing memorable.
7

Workbench — Master–Detail

Persistent list beside a detail pane · no modals ever · dense · keyboard-first
Open Workbench

The one that changes the layout model rather than the styling. A list pane sits permanently beside a detail pane, so you work through alarms, assets or endpoints without navigating away and rebuilding your filters. Nothing opens in a modal — creating a record adds a draft to the list and edits it in the detail pane. Warm neutrals, one indigo accent, 26px rows, j/k to move and e to acknowledge.

Strengths

  • Best fit for the actual job. Alarm triage is a queue, and this is the layout queues want.
  • Highest density. ~22 table rows and a 5-cell fact grid in the same space.
  • No lost work. A draft survives navigation; nothing is trapped behind a modal.
  • Rewards daily users — keyboard flow gets genuinely fast with practice.

Trade-offs

  • Biggest build. Three-pane routing and draft state are real engineering, not restyling.
  • Weakest on mobile — the split has to collapse to list-then-detail navigation.
  • Unfamiliar to occasional users, who may not find the detail pane's tabs.
  • Dense by default can feel cramped to managers who only read summaries.

There is no single winner, and the honest read is that the choice depends on who the primary user is. If it is a control-room operator working the platform all shift, Workbench wins on fit and pays for its build cost. If the platform gets demonstrated to buyers and handed to occasional users across several sites, Nimbus wins. If longevity and low maintenance matter most, Slate wins.

A viable hybrid

Slate's surface treatment with Workbench's layout for queue-shaped screens. Take Slate's palette, hairline structure and monochrome restraint as the design system — it is the cheapest to build and the slowest to date. Then apply the master–detail layout only where the work is genuinely a queue: Alarms, Assets and API Endpoints. Dashboards, Analytics and Settings stay single-pane. That gets the density and triage flow where they earn their cost, without three-pane routing across the whole app or a second visual language to maintain.

Scope, unchanged

These are presentation-layer proposals only. No concept changes an API contract, a database table, a calculation, a validation rule, an RBAC decision or an integration. Every screen is styled from real routes and real fields already in the platform, and each is a self-contained HTML file with inline CSS and no external requests — openable directly in any browser.
